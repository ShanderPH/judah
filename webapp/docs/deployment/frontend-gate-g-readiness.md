- The backend migration `0025_administrative_action_audit` is additive. The previous backend ignores the table, so rollback preserves it by default.

## Rollback

1. Record the last healthy Vercel Production deployment before merge.
2. If auth, RBAC, BFF, CSP or rendering regresses, promote/redeploy the previous Vercel deployment without changing backend data.
3. For backend regression, redeploy the preceding Railway SHA. Keep `support_administrative_action_audits`; reverse the migration only with explicit approval and a retention/export decision.
4. Never retry sync, assignment, force-reassign or another administrative mutation automatically during rollback.

## Remaining path to deploy

1. Commit only the implementation/request artifacts, excluding unrelated worktree drift and local `.playwright-mcp` data.
2. Integrate current `origin/main`, push the branch and open a ready PR to `main`.
3. Wait for required GitHub checks, approval/code-owner review and Vercel Preview.
4. Run the Preview smoke and attach the deployment URL/status to the PR.
5. Resolve or explicitly accept the dev-only ESLint advisory exception before merge.
6. Merge only after approval; then execute V-06 against the exact production SHA and Vercel deployment.
